# 2026.11.16-critical

**Date:** 2026-11-16 · **Kind:** critical · **Package version:** 2026.11.16

The desktop app now works from a cold start and shows, at every moment, what it
is doing. If you use the desktop preview, update: on a machine where the model
server was not already running, the previous release could wait forever on
"Starting the model".

## Highlights

- **Live progress during audio preparation.** Audio extraction, speech detection
  and chunk cutting each show measured progress, speed and remaining time. On a
  two-hour recording this phase takes close to a minute, which previously showed
  no feedback at all.
- **Live map of the recording.** The waveform of the selection shows the
  preparation scan, the speech-probability curve and its threshold, where each
  chunk was cut, and the state of every chunk: waiting, in progress, transcribed,
  no speech or failed. Hover a chunk for its number, times and state.
- **Latest transcribed lines** appear while the model works. They are read from
  the local checkpoint; transcript text never enters the event stream.
- **"Last update" heartbeat.** It counts the seconds since the pipeline last
  reported progress (CPU and GPU samples do not count) and turns red after 45 s,
  so you can tell a slow step from a stalled one when you come back to the window.
- **Close with confirmation.** Closing the window during a run asks whether to
  keep working or to stop and close. Stopping ends the worker and everything it
  started; completed chunks stay in the checkpoint, the recording stays in the
  queue, and a new run with the same settings resumes from there.

## Fixes

- **Critical:** the desktop no longer hangs on "Starting the model" when it has to
  start the model server itself. The launcher left the server holding the pipe the
  worker was reading, so the read never ended. Its output now goes to
  `process/desktop-runtime/launcher.log`.
- Closing the window during a run no longer fails silently, and a forced close no
  longer leaves an orphaned worker holding the run lock.
- The desktop now rejects a job identifier that would point outside the process
  folder when it reads the live text preview.

## For integrations

- `stage.progress` events now also cover `stage` = `preparation`, with a `step`
  field (`audio_extraction`, `speech_detection`, `chunk_slicing`); the final speech
  detection report carries a coarse `activity` curve and its `threshold`.
- `job.prepared` carries `spans`, the planned `[start, end]` seconds of every chunk.
- Speech detectors may accept an optional `progress` callback; detectors without
  it keep working unchanged. See [run events](../events.md).

## Upgrade notes

- No configuration change is needed. Pull the update and restart `desktop.cmd`.
- The package version is now the release date (`2026.11.16`); see [versions](README.md#versions).

## Verification

- A 2 h 10 min Italian recording through the real desktop window from a cold start:
  the model started in about 10 s on CUDA; 533 chunks (532 ok, 1 without speech,
  0 failed) in 4 min 58 s in total on one desktop NVIDIA GPU.
- A 7-minute interval of another recording with the live map: measured progress for
  every preparation step, the 37-chunk plan, two chunks in progress at a time and a
  heartbeat that never exceeded about one second.
- Full automated suite, lint and the WebView layout check at 1100x830, now also with
  the latest-lines box visible. Details in
  [verification](../verification.md#desktop-model-start-close-confirmation-and-live-feedback-2026-11-13).

## Known limits

- Windows only; the Linux and macOS desktop are not verified.
- A run cannot yet be cancelled without closing the window.
- In Task Manager the worker still appears as `python.exe`.
